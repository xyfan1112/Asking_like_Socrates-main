# 一、三个实验分别是什么

| 实验 | 模型 | 是否训练 | 训练数据 | 主要目的 |
|---|---|---:|---|---|
| B0 | `RS-EoT-7B` | 否 | 无 | 测量基础模型在DOTA OBB上的zero-shot能力 |
| B1 | `RS-EoT-7B-DOTA128-Direct-Merged` | 是 | Direct OBB | 验证直接类别条件OBB监督是否有效 |
| B2 | `RS-EoT-7B-DOTA128-Socratic-Merged` | 是 | Direct OBB + 严格筛选Socratic轨迹 | 验证多轮视觉思考是否进一步改善定位 |

对应的模型键：

```text
B0：rs_eot
B1：rs_eot_b1_direct
B2：rs_eot_b2_socratic
```

三个实验必须使用同一套：

```text
验证图像
测试prompt
坐标制
采样参数
IoU阈值
指标脚本
```

否则B0、B1、B2不能进行公平比较。

```text
原始DOTA OBB
│
├── 数据审计、丢弃越界框、生成有效Direct和DOTA-Ref

    → 测试

统一测试：
1. 类别条件DOTA OBB检测
2. DOTA-Ref K=1定位
3. DOTA-Ref K=5稳定性
4. 预测框可视化
5. B0/B1/B2指标汇总
```

### 为什么使用fresh

`fresh`保证：

```text
旧raw不会混入
旧Query ID不会resume
旧Prompt轨迹不会混入
旧strict与merge不会被误用
```

只有同一轮任务因断电或意外中断，且Parquet、Prompt、代码、坐标制完全没变时，才使用：

```bash
bash data_layer/official_socratic/02_run_official_generation.sh \
  settings.json train full 0 auto
```

# 十、统一测试协议说明

## 10.1 DOTA类别条件检测

主协议：

```text
dota_class_conditioned
K=1
temperature=0
坐标=[0,1000]
```

任务形式：

```text
给定图像和类别名称
→ 输出该类别在图中的全部OBB
```

主要指标：

```text
mAP@0.5
mAP@0.5:0.95
输出协议成功率
格式失败数
API错误数
token截断数
```

只有：

```text
status=VALID
```

时才能解释mAP。

`status=INVALID`时，先修复遗漏行、API错误或token截断，不能把mAP=0当成模型能力。

---

## 10.2 DOTA-Ref K=1

主协议：

```text
ref_grounding
K=1
temperature=0
```

主要指标：

```text
Parse Success
Class Accuracy
mIoU
IoU@0.5
IoU@0.7
IoU@0.75
```

这是判断单次稳定定位能力的主要指标。

---

## 10.3 DOTA-Ref K=5

扩展协议：

```text
ref_grounding_k5
K=5
temperature=0.35
top_p=0.9
```

主要指标：

```text
Avg@5
Conv@5
Pass@5
```

解释：

```text
Avg@5：5次运行的平均成功率
Conv@5：至少多数运行成功
Pass@5：5次中至少一次成功
```

K=5用于观察稳定性，不替代K=1主结果。

# 十三、如何解释B0、B1、B2结果

## 13.1 B1优于B0

可以支持：

```text
Direct OBB SFT能够让RS-EoT学习DOTA类别条件检测格式和坐标回归。
```

重点看：

```text
Parse Success是否提高
Class Accuracy是否提高
mIoU是否提高
mAP是否提高
```

---

## 13.2 B2优于B1

可以支持：

```text
在相同Direct监督基础上，经过严格门控的Socratic视觉思考轨迹
能够进一步改善目标消歧、类别判断或空间定位。
```

必须确认B2使用的Socratic数据确实包含：

```text
Grounding轨迹
Classification轨迹
正确目标区域
无明显语义矛盾
```

---

## 13.3 B2不如B1

可能原因：

```text
Socratic轨迹数量太少
思考轨迹存在错误视觉证据
轨迹过长，稀释坐标监督
分类轨迹占比过高
Grounding轨迹空间证据太粗
B1与B2训练token/steps不一致
```

此时先检查数据质量，不要直接认为“思考无效”。
